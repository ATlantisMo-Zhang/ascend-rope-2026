# Ascend C RoPE 算子实现与性能优化

本项目整理自 **2026 CANN 挑战赛京津东北赛区初赛 RotaryPosEmb 的参赛实践**，是参赛代码与实验记录的工程化整理。使用 Ascend C 在昇腾 NPU 上完成旋转位置编码，保留首个全通过版本、最终实现、逐点性能记录和失败实验，展示数值精度、数据搬运、核内复用与实验取舍。

这是单算子工程。频率、三角函数和旋转均在 NPU 计算；Host 读取元数据、选择分块并启动一个完整 kernel。

- 最终选定源码：在线训练记录 **721646**（2026-10-11），15/15 Pass；源码与平台回读 SHA256 一致。
- 同源重交：在线训练记录 **826799**（2026-10-15），15/15 Pass，没有修改源码；[完整记录](evidence/platform/826799.json)与[摘要](evidence/resubmission-20261015.json)保留。

## 技术内容

1. **精度处理**：补偿 FP32 的 log/exp 与倒数计算、角度归约、FP16 NaN/Inf 修复，以及零位置按位保留。
2. **数据布局与复用**：token 分组多核分工、head 分块、连续搬运与非对齐尾部处理；同一 token 的三角系数在多个 head 间复用。
3. **核内批处理**：按 UB 预算组织多个 token 的角度缓存和旋转，管理 DMA、队列及计算依赖。
4. **可追溯实验**：保存源码 SHA256、完整 15 点结果和退化候选，用统一评分参照辅助历史版本选择。

最终源码保持比赛版本原样，包含用于隔离设备路径的代码重复。阅读建议先看 v3 与设计说明，再定位最终路径；没有为排版或可读性改写已验证代码。

## 先在普通电脑核对材料

在仓库根目录运行，只需要 Python 标准库：

```bash
python tools/verify_artifacts.py
```

脚本核对文件指纹、最终源码、15 点记录、CSV 耗时比和历史选版计算；它不执行 NPU kernel。

真正构建和运行需要 Linux、匹配的 CANN/Ascend C 工具链及昇腾 NPU，具体步骤见[复现说明](docs/validation.md)。本次整理未重新执行 Ascend 编译或 NPU 测量。
