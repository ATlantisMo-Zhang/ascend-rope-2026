## 技术演进主线

1. **先取得正确性基线**：用补偿 FP32 频率计算处理长位置下的误差，得到 v3 全通过记录。
2. **减少细碎工作**：向量化特殊值修复、head 分块与连续搬运，复用同一 token 的三角系数。
3. **按资源预算批处理**：UB 预算约束多 token 角度缓存、window 布局与队列容量，让数据布局与 repeat/stride 配合。
4. **保留有效路径并拒绝退化**：原路径与向量频率路径隔离，按公开数学适用域路由；保存全部逐点结果，再决定保留或回退。

上述机制在最终源码中可以定位；每项的独立性能贡献需要独立实验。本次以代码和已保存记录讲清实现，不补写不存在的因果证明。

## 路径隔离与控制实验

680176 将种子树逻辑并入原类，12、8 点出现局部改善，同时其他点退化。680947 保留原设备前缀，把树路径放入独立命名空间，再按 theta 与 D 的公开数学资格选择完整路径。678561 与其同源控制 681070 提供了测量变化的参照。

这支持“保存局部线索、尝试隔离退化”的实验方法，但不能证明具体寄存器或编译资源是根因。最终采用的是当时证据支持的取舍，不是已证明树路径在所有适用输入上更快。

708382 删除部分角度归约工作，虽然 15 点全部通过，仍产生多个点退化，未替换最佳版本。源码指令减少不自动等于用时下降；具体硬件原因缺少 profile/汇编证据。

## 最终版本为什么这样选

比赛收尾保存了 163 份可恢复、完整 Pass15 的平台记录，并用同一 tbest 比较。最高的 686549 与次高的 680947 源码完全相同，最终再提交同源代码得到 721646。选版依据是完整记录与源码一致性，没有选“最后一个候选”。

本公开包保留该 163 条选版数据的脱敏导出 [selection.json](../evidence/selection.json)，只收录少量用于讲解的源码快照；不是把全部版本重新评测一遍，也不是把所有历史实现纳入公开仓库。
